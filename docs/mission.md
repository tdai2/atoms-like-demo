# Mission — Atoms 风格 AI 应用生成平台

> 本文档是整个项目的顶层纲领，覆盖产品、设计、前端与后端的方向和边界。
> 各子目录（如 `app/frontend`）的技术说明须服从本文档的方向与边界。

## 一句话使命

让任何有想法的人，用一句自然语言描述，就能得到一个真正能运行、能分享、能持续迭代的应用。

## 我们要解决的问题

今天把一个想法变成可用的软件，门槛依然很高：

- **技术门槛**：懂业务的人往往不写代码，懂代码的人未必有时间做小而美的工具。
- **启动成本**：从选技术栈、搭脚手架、配置构建到部署上线，真正开始写业务逻辑之前就要消耗大量精力。
- **迭代摩擦**：改一个需求要在设计稿、代码、构建、发布之间来回穿梭，反馈周期以天计。
- **现有 AI 工具的断裂**：多数工具只生成代码片段，不负责跑得起来、也不负责后续修改，最后一公里仍然留给人。

## 我们的主张

**生成的终点不是代码，而是一个活着的应用。**

- 用户提交的是意图，拿到的应该是可访问的链接，而不是一堆待整理的文件。
- 生成过程必须**可见**。用户有权看到需求如何被拆解、选了什么技术栈、构建是否通过、测试是否通过，而不是面对一个黑盒等待。
- 修改应该是**对话式**且**增量**的。追加一句需求就该精准改动对应部分，而不是推倒重来。
- 默认交付**可运行、可发布、可继续演进**的完整产物。

## 产品原则

这六条原则约束项目中的每一次决策，包括界面、数据模型与接口设计。

1. **端到端，不留半成品**
   前端界面、数据结构、接口与部署一次贯通。任何交付物都不应停留在"看起来像"的阶段。

2. **过程透明优于结果惊喜**
   实时展示解析需求、生成方案、编写代码、构建校验、测试验证、发布预览六个阶段的真实状态。构建或测试失败都要说清失败原因。

3. **增量胜过重写**
   每一轮对话只改动必要的部分，保留用户已确认的成果。用户的迭代不应该带来回退的风险。

4. **默认就很好看**
   生成结果自带成体系的设计语言——配色、字体、间距、圆角相互协调，而不是拼凑出的通用模板感。

5. **用户始终拥有出口**
   代码归用户所有，可导出、可自行托管。平台提供加速，不制造锁定。

6. **克制胜过堆砌**
   只做用户真正要的那件事。不用"更完整""更专业"当作扩大范围的理由。

## 目标用户

| 人群 | 核心诉求 |
|------|---------|
| 独立开发者 | 跳过脚手架与部署，把时间花在产品判断上 |
| 产品经理 / 创业者 | 不依赖排期就能把想法做成可点击、可验证的真实产品 |
| 团队内部工具需求方 | 快速得到运营看板、审批流程等长期排不上优先级的小工具 |
| 设计师 | 把设计意图直接变成可交互的实现，而不是停在静态稿 |

## 项目范围

整个项目由以下几层构成，当前各层的落地程度不同，但方向统一。

| 层 | 职责 | 当前状态 |
|----|------|---------|
| 体验层 | 需求输入台、生成时间线、应用预览窗、模板库、定价、我的项目 | 已落地（`app/frontend`） |
| 设计系统 | 暗色工程风的颜色/字体/间距/动效规范 | 已落地（`app/frontend/DESIGN.md`） |
| 生成引擎 | 需求解析、方案规划、代码生成、构建校验、测试验证、发布预览 | 已落地：六阶段由真实模型调用驱动，后台异步执行（`app/backend/services/generation*.py`、`pipeline_runner.py`） |
| 数据层 | 账号体系、项目与版本持久化、文件存储 | 已落地：账号复用平台认证，项目/任务/版本/配额落 PostgreSQL，产物存对象存储 |
| 发布层 | 构建托管、预览链接、自定义域名 | 预览链接已落地（产物托管于对象存储，按对象键即时解析，不落库）；自定义域名未接入 |
| 测试层 | 测试用例生成与维护、产物上的执行、运行历史 | 已落地：用例可自动或手动维护，执行在真实产物源码上做确定性断言，结果与逐例明细落库可回溯（`app/backend/services/test_suite.py`、`src/components/TestSuitePanel.tsx`） |

仍未落地的是发布层的自定义域名、以及 Bug 自动修复、对话式增量修改、团队协作等后续阶段能力。它们在产品中以真实标签的入口呈现，点击进入统一的建设中说明页，而不是伪造成已完成的功能——这是原则 1 与原则 2 的直接体现。

## 成功的定义

我们用这些信号判断使命是否在推进：

- **首次成功率**：用户第一次提交需求后，多久拿到一个愿意分享出去的链接。
- **迭代深度**：一个项目平均经历多少轮对话式修改——说明用户真的在用，而不只是试了一次。
- **留存的产物**：有多少生成的应用在一周后仍被访问，而不是生成即废弃。
- **信任度**：用户是否愿意把它用在真实业务场景，而不仅是玩具项目。

## 不做什么

明确划定边界，避免稀释核心价值：

- 不做通用代码补全工具，我们交付的是应用而非片段。
- 不做拖拽式可视化搭建器，自然语言与代码是我们的主要界面。
- 不为了演示效果生成看得见但点不动的假界面。
- 不通过锁死导出来提升留存。

## 我们相信

软件创造的能力不该被编程技能所限定。当描述一个想法与实现一个想法之间的距离趋近于零，会有大量本不会被做出来的产品诞生——那些太小众、太具体、太不值得立项的需求，终于有机会被满足。

这是我们要抵达的地方。
