# Project Summary

This project is an Atoms-style product demo for an AI application-generation platform. Users submit natural-language app requests or choose presets, follow a transparent six-stage generation workflow, and preview local mini-applications such as dashboards, coffee subscription pages, and team task managers.

Stage two is implemented with an Atoms Cloud backend. Accounts use the platform authentication system, while projects, build tasks, versions, and usage quotas persist in PostgreSQL. Generation runs as a server-side state machine that the frontend polls, allowing signed-in users to view, retry, and delete their own projects.

The frontend provides the landing generator, project list at `/projects`, project details at `/projects/:id`, account flows, changelog, templates, pricing, blog pages, and responsive UI states. Real model generation and externally accessible deployment URLs are not connected yet; solution specifications and stage logs are derived by the backend, and previews remain local React components. Billing, object-storage publishing, conversational editing, GitHub synchronization, and real test execution remain future work.

# Project Module Description

- **Landing and generator**: Accepts prompts and presets, creates persisted generation projects, polls server-side progress, displays quota errors, and renders the resulting local preview.
- **Generation pipeline**: Advances through requirements parsing, solution generation, code writing, build validation, test validation, and preview publishing.
- **Project management**: Lists the authenticated user's projects, displays quota usage, supports deletion, and provides loading, empty, anonymous, and retryable error states.
- **Project detail**: Shows pipeline status, solution specification, test report, version history, and retry actions.
- **Authentication**: Uses the Atoms account system with loading, authenticated, and anonymous states. The previous duplicate Axios authentication flow has been removed.
- **Quota management**: Persists per-period usage and prevents generation after quota exhaustion. Retries do not consume quota again.
- **Backend orchestration**: Coordinates project creation, task state transitions, version records, quota checks, failures, and retries.
- **Entity persistence**: Provides user-scoped records for projects, build tasks, project versions, and usage quotas.
- **Mini-app previews**: Selects and renders dashboard, coffee subscription, or team task manager variants using request keywords.
- **Template library**: Supports category filtering for Data, Marketing, Tools, and Commerce with resettable empty states.
- **Changelog**: Renders six static releases with summaries, tags, categorized filters, counts, version anchors, latest-release highlighting, and empty states.
- **Navigation and pricing**: Provides responsive global navigation, changelog access, pricing tiers, and calls to action.
- **Blog**: Provides Markdown-based article pages, index pages, prerendering, and sitemap generation.
- **Supporting routes**: Includes sign-in, authentication callback/error handling, logout callback, settings, protected admin routing, and under-construction pages.
- **Delivery boundary**: Static marketing content remains local. Accounts and generation records are persisted through the backend. Deployment URLs and real model execution remain outside the current stage.

# Usage

Install frontend dependencies and start development:

```bash
cd app/frontend
pnpm install
pnpm run dev
```

Run frontend checks and build:

```bash
pnpm run lint
pnpm run build
```

Install backend dependencies:

```bash
cd app/backend
python -m pip install -r requirements.txt
```

Apply database migrations when backend environment configuration is available:

```bash
alembic upgrade head
```

Run the backend using the project’s configured FastAPI application entry point or the provided application startup script:

```bash
cd app
./start_app_v2.sh
```

To review the product, authenticate with an Atoms account, submit a prompt from the landing page, monitor the six persisted stages, inspect the local preview and test report, then open the projects area to review the saved project and its detail page. The changelog is available through the global navigation.
