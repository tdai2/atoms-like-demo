# Project Summary

This project is an Atoms-style product demo for an AI application-generation platform. Users submit natural-language app requests or choose presets, follow a transparent six-stage generation workflow, and preview local mini-applications such as dashboards, coffee subscription pages, and team task managers.

The application uses an Atoms Cloud backend for authentication, project persistence, generation tasks, versions, and PostgreSQL-backed usage quotas. Signed-in users can create, monitor, retry, inspect, and delete their own projects.

The frontend includes the landing generator, project list at `/projects`, project details at `/projects/:id`, authentication flows, signup guidance at `/signup`, changelog, templates, pricing, blog pages, responsive navigation, and local React previews. Unauthenticated users selecting Start Free are directed to the signup landing page with their intent preserved; the page then hands off to the shared Atoms account flow. Authenticated users see their account email and a logout action. After authentication, users return to the homepage generator with the input area focused.

Real model execution, externally accessible deployment URLs, billing, object-storage publishing, conversational editing, GitHub synchronization, and real test execution remain future work.

# Project Module Description

- **Landing and generator**: Accepts prompts and presets, creates persisted generation projects, polls server-side progress, displays quota errors, and renders local previews.
- **Start Free flow**: Stores intent in session storage, sends anonymous users to `/signup`, and returns authenticated users to the homepage generator with input focus.
- **Signup landing page**: Explains account benefits and routes users into the shared Atoms registration/login page. Existing users can navigate to `/signin`.
- **Authentication**: Uses the Atoms account system with loading, authenticated, and anonymous states. Authenticated navigation displays the account email and logout action.
- **Generation pipeline**: Advances through requirements parsing, solution generation, code writing, build validation, test validation, and preview publishing.
- **Project management**: Lists authenticated users’ projects, displays quota usage, supports deletion, and provides loading, empty, anonymous, and retryable error states.
- **Project detail**: Shows pipeline status, solution specification, test report, version history, and retry actions.
- **Quota management**: Provides 20 Starter generations per natural month, resets across months, deducts one generation per attempt, and reports exhaustion explicitly. Retries do not consume quota again.
- **Backend orchestration**: Coordinates project creation, task transitions, version records, quota checks, failures, and retries.
- **Entity persistence**: Provides user-scoped records for projects, build tasks, project versions, and usage quotas.
- **Mini-app previews**: Selects dashboard, coffee subscription, or team task manager variants using request keywords.
- **Template library**: Supports category filtering for Data, Marketing, Tools, and Commerce with resettable empty states.
- **Changelog**: Renders static releases with summaries, tags, filters, counts, version anchors, latest-release highlighting, and empty states.
- **Navigation and pricing**: Provides responsive global navigation, account actions, Start Free CTAs, changelog access, pricing tiers, and calls to action. Plan selection still leads to a billing placeholder.
- **Blog**: Provides Markdown-based article pages, index pages, prerendering, and sitemap generation.
- **Supporting routes**: Includes sign-in, signup, authentication callback/error handling, logout callback, settings, protected admin routing, and under-construction pages.
- **Delivery boundary**: Marketing content remains local; accounts and generation records are backend-persisted; deployment and real model execution are not connected.

# File Description Inventory

- **Workspace documentation**: `README.md`, `.atoms/`, `.wiki.md`, `docs/mission.md`, and `docs/plan.md`.
- **Backend entry and configuration**: `app/backend/main.py`, `lambda_handler.py`, `core/*`, `dependencies/*`, and `alembic/*`.
- **Backend models**: Project, build task, project version, usage quota, authentication, and shared base models under `app/backend/models/`.

- **Backend services**: `services/generation.py` owns the six-stage state machine, quota checks, version creation, failure handling, and retry behavior.
- **Frontend shell and routing**: `src/App.tsx` and `main.tsx` define application routing, authentication routes, the `/signup` route, and global Start Free intent handling.
- **Signup flow**: `src/pages/SignUp.tsx` provides the local registration landing page and routes users into the Atoms account flow.
- **Project frontend**: `pages/Projects.tsx`, `pages/ProjectDetail.tsx`, `hooks/useProjects.ts`, and `lib/projects.ts` implement project queries, polling, retry, deletion, detail views, and API types.
- **Authentication frontend**: `contexts/AuthContext.tsx`, `hooks/useAuthStatus.ts`, `pages/SignIn.tsx`, `pages/SignUp.tsx`, `pages/LogoutCallbackPage.tsx`, `pages/AuthCallback.tsx`, `pages/AuthError.tsx`, and `components/ProtectedAdminRoute.tsx`.

- **Navigation**: `components/SiteHeader.tsx` renders responsive navigation, anonymous login and Start Free actions, and authenticated account/logout controls without duplicate mobile CTAs.
- **Changelog**: `data/changelog.ts` stores release records; `pages/Changelog.tsx` renders the timeline and filters.
- **Product components**: `components/MiniApp.tsx` renders local generated previews; shared loading and UI primitives provide reusable interaction states.
- **Static content and styling**: `data/site.ts`, `index.css`, `App.css`, `DESIGN.md`, and Tailwind/PostCSS configuration.
- **Blog and SEO**: `components/blog/*`, `lib/blog.ts`, `prerender/*`, `index.html`, and `public/robots.txt`.
- **Tooling and diagnostics**: `package.json`, `pnpm-lock.yaml`, Vite, TypeScript, ESLint, Tailwind, frontend configuration files, and backend application logs.

# Usage

Install frontend dependencies and start development:

```bash
cd app/frontend
pnpm install
pnpm run dev
```

Run frontend checks and build:

```bash
pnpm run lint
pnpm run build
```

Install backend dependencies:

```bash
cd app/backend
python -m pip install -r requirements.txt
```

Apply database migrations when backend environment configuration is available:

```bash
alembic upgrade head
```

Run the backend using the configured FastAPI entry point or startup helper:

```bash
cd app
./start_app_v2.sh
```

To review the product, verify that anonymous Start Free actions open `/signup`, the signup landing page routes into the shared Atoms account flow, and authenticated navigation displays the account email with a logout action. After authentication, confirm that users return to the homepage, the pending intent is consumed, and the generator input area receives focus. Then submit a prompt and monitor persisted generation stages, quota usage, saved projects, project details, previews, test reports, and changelog content.
