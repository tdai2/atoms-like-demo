# Project Summary

This project is an Atoms-style product demo for an AI application-generation platform. Users submit natural-language app requests or choose presets, follow a transparent six-stage generation workflow, and preview generated applications through real stored artifacts.

Stage Three now replaces keyword-driven mock generation with real AI-backed requirements analysis, solution planning, and code generation. Generated artifacts are uploaded to object storage and previewed through dynamically resolved iframe URLs. Projects remain user-scoped and persist solutions, artifacts, test results, versions, and preview metadata.

The generation pipeline now includes atomic quota deduction, stage claiming, stale-stage recovery, retry-safe execution, structured-output repair, and quota refunds when model execution fails. Authentication-aware navigation and logout callback routing remain supported.

Frontend lint and production build pass. Real AI, object storage, authentication, and service-layer verification pass in the configured environment. Full six-stage verification is currently blocked by insufficient external AI balance rather than an application failure.

# Project Module Description

- **Landing and generator**: Accepts prompts and presets, starts persisted generation projects, polls stage progress, displays quota errors, and renders stored-artifact previews.
- **Authentication-aware navigation**: Displays account controls for authenticated users and login or Start Free actions for anonymous users.
- **Logout handling**: Clears local state, supports fallback behavior, routes platform logout callbacks to the homepage, and maintains dark styling.
- **Signup and Start Free flow**: Preserves anonymous intent through signup and authentication, then focuses the generator after login.
- **Real generation pipeline**: Runs requirements parsing, solution planning, code generation, build validation, test validation, and artifact publishing using real model and storage services.
- **Structured-output recovery**: Repairs truncated JSON, trailing commas, unclosed strings or brackets, and Markdown-wrapped model output locally before attempting a stricter model fallback.
- **Project management**: Lists user projects, displays quota usage, supports deletion, polling, retry, and appropriate loading, empty, anonymous, and error states.
- **Project detail**: Shows pipeline status, solution specifications, test reports, version history, stored-artifact preview, and an Open Preview action.
- **Artifact storage**: Uploads generated products to object storage and resolves preview addresses from object keys at request time instead of persisting expiring signed URLs.
- **Quota management**: Provides 20 Starter generations per natural month, deducts atomically per attempt, does not charge retries again, and refunds failed model attempts without leaving partial projects or tasks.
- **Concurrent execution control**: Atomically claims stages and reclaims stale in-progress work to prevent duplicate polling execution.
- **Backend orchestration**: Coordinates project ownership, task transitions, AI calls, artifact publication, versions, failures, retries, quota handling, and cleanup.
- **Entity persistence**: Stores user-scoped projects, build tasks, project versions, usage quotas, solutions, artifacts, and test results.
- **Template library**: Supports filtering for Data, Marketing, Tools, and Commerce.
- **Changelog and blog**: Provides release filtering, version navigation, static content, Markdown articles, prerendering, and sitemap generation. New releases are added at the top of `src/data/changelog.ts`.
- **Navigation and pricing**: Provides responsive navigation, account actions, Start Free CTAs, pricing tiers, and billing placeholders.
- **Supporting routes**: Includes sign-in, signup, authentication callback/error handling, logout callback, settings, protected admin routing, and under-construction pages.
- **Documentation maintenance**: Tracks Stage Three architecture, decisions, progress, verification results, and known external blockers.

# Usage

Install frontend dependencies and start development:

```bash
cd app/frontend
pnpm install
pnpm run dev
```

Run frontend checks and build:

```bash
pnpm run lint
pnpm run build
```

Install backend dependencies:

```bash
cd app/backend
python -m pip install -r requirements.txt
```

Apply database migrations when backend environment configuration is available:

```bash
alembic upgrade head
```

Run the backend using the configured FastAPI entry point or startup helper:

```bash
cd app
./start_app_v2.sh
```

Run Stage Three verification from the backend directory:

```bash
cd app/backend
python verify_stage3.py
python verify_quota_refund.py
python verify_pipeline.py
```

`verify_stage3.py` validates model calls, artifact upload and retrieval, public preview resolution, and successful parsing/planning/code generation. `verify_quota_refund.py` validates that unavailable models refund quota and remove partial records. The full pipeline script requires sufficient external AI balance.

For release verification, confirm that the changelog remains synchronized and that authentication-aware navigation, logout recovery, project generation, quota behavior, saved projects, detail views, and iframe previews work correctly.
