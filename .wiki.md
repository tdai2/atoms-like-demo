# Project Summary

This project is an Atoms-style product demo for an AI application-generation platform. Users submit natural-language app requests or choose presets, follow a transparent six-stage generation workflow, and preview local mini-applications such as dashboards, coffee subscription pages, and team task managers.

The platform supports authentication, user-scoped project persistence, generation tasks, versions, PostgreSQL-backed quotas, account-aware navigation, logout recovery, and project management through Atoms Cloud. Users can create, monitor, retry, inspect, and delete projects.

The frontend includes the landing generator, authentication flows, account navigation, project list and detail views, templates, pricing, changelog, blog pages, responsive navigation, and local React previews. The changelog uses `src/data/changelog.ts` as its release data source, with v0.7.0 as the latest release.

The current documentation has been synchronized across the root README, frontend README, delivery plan, wiki, and team context files. This documentation-only update did not change application source code.

Real model execution, external deployment URLs, billing, object-storage publishing, conversational editing, GitHub synchronization, and real test execution remain future work.

# Project Module Description

- **Landing and generator**: Accepts prompts and presets, creates persisted generation projects, polls progress, displays quota errors, and renders local previews.
- **Authentication-aware navigation**: Switches header account controls according to authentication state and provides login or free-start actions for anonymous users.
- **Logout handling**: Supports platform logout, local state cleanup, fallback handling, and homepage redirection.
- **Signup and Start Free flow**: Preserves anonymous intent through signup and authentication, then focuses the generator after login.
- **Generation pipeline**: Covers requirements parsing, solution generation, code writing, build validation, test validation, and preview publishing.
- **Project management**: Lists user projects, displays quota usage, supports deletion, and provides loading, empty, anonymous, and retryable error states.
- **Project detail**: Shows pipeline status, solution specifications, test reports, version history, and retry actions.
- **Quota management**: Provides 20 Starter generations per natural month, resets monthly, deducts one generation per attempt, and excludes retries from additional usage.
- **Backend orchestration**: Coordinates project creation, task transitions, version records, quota checks, failures, and retries.
- **Entity persistence**: Stores user-scoped projects, build tasks, project versions, and usage quotas.
- **Mini-app previews**: Selects dashboard, coffee subscription, or team task manager variants using request keywords.
- **Template library**: Supports filtering for Data, Marketing, Tools, and Commerce.
- **Changelog and blog**: Provides release filtering, version navigation, static content, Markdown articles, prerendering, and sitemap generation. New releases are added at the top of the changelog data array and automatically become latest.
- **Navigation and pricing**: Provides responsive navigation, account actions, Start Free CTAs, pricing tiers, and billing placeholders.
- **Supporting routes**: Includes sign-in, signup, authentication callback/error handling, logout callback, settings, protected admin routing, and under-construction pages.
- **Documentation maintenance**: Keeps project scope, release status, implementation plans, and team progress records synchronized.

- **Start Free flow**: `src/lib/startFree.ts`, `src/hooks/useStartFree.ts`, and `src/components/StartFreeIntentWatcher.tsx` preserve intent across authentication.
- **Project frontend**: `src/pages/Projects.tsx`, `src/pages/ProjectDetail.tsx`, `src/hooks/useProjects.ts`, and `src/lib/projects.ts` implement project queries, polling, retry, deletion, and detail views.

- **Frontend documentation**: `app/frontend/README.md` documents architecture, commands, and changelog maintenance rules.
- **Planning documentation**: `docs/plan.md` records the staged delivery plan, state-machine decisions, and implemented account/changelog work.

# Usage

Install frontend dependencies and start development:

```bash
cd app/frontend
pnpm install
pnpm run dev
```

Run frontend checks and build:

```bash
pnpm run lint
pnpm run build
```

Install backend dependencies:

```bash
cd app/backend
python -m pip install -r requirements.txt
```

Apply database migrations when backend environment configuration is available:

```bash
alembic upgrade head
```

Run the backend using the configured FastAPI entry point or startup helper:

```bash
cd app
./start_app_v2.sh
```

For release verification, confirm that the changelog displays v0.7.0 as the newest release, marks it as latest, keeps filtering and version navigation synchronized, and renders the release entry correctly. Also verify authentication-aware navigation, logout recovery, project generation, quotas, saved projects, project details, and previews.

This update changed documentation files only. No additional build was required; prior lint, production build, and changelog rendering checks remain the relevant verification baseline.
