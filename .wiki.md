# Project Summary

This project is an Atoms-style product demo for an AI application-generation platform. Users submit natural-language app requests or choose presets, follow a transparent six-stage generation workflow, and preview local mini-applications such as dashboards, coffee subscription pages, and team task managers.

The application uses an Atoms Cloud backend for authentication, project persistence, generation tasks, versions, and PostgreSQL-backed usage quotas. Signed-in users can create, monitor, retry, inspect, and delete their own projects.

The frontend includes the landing generator, project list, project details, authentication flows, signup guidance, changelog, templates, pricing, blog pages, responsive navigation, and local React previews. Homepage account actions now rely on the shared authentication state: anonymous users see login and free-start actions, while authenticated users see their email and logout controls. The unrelated fixed footer login link has been removed.

Logout now supports both GET and POST requests, safely falls back when the external logout URL cannot be constructed, and clears local authentication state even if the platform logout request fails.

Real model execution, externally accessible deployment URLs, billing, object-storage publishing, conversational editing, GitHub synchronization, and real test execution remain future work.

# Project Module Description

- **Landing and generator**: Accepts prompts and presets, creates persisted generation projects, polls server-side progress, displays quota errors, and renders local previews.
- **Authentication-aware navigation**: Displays login and free-start actions for anonymous users and account email/logout controls for authenticated users.
- **Logout handling**: Supports resilient platform logout, local state cleanup, and return to the homepage after logout failures.
- **Homepage footer**: Provides documentation and changelog links without a duplicate login entry point.
- **Signup and Start Free flow**: Preserves anonymous intent, routes users through signup and account authentication, and focuses the generator after authentication.
- **Generation pipeline**: Advances through requirements parsing, solution generation, code writing, build validation, test validation, and preview publishing.
- **Project management**: Lists authenticated users’ projects, displays quota usage, supports deletion, and provides loading, empty, anonymous, and retryable error states.
- **Project detail**: Shows pipeline status, solution specification, test report, version history, and retry actions.
- **Quota management**: Provides 20 Starter generations per natural month, resets across months, deducts one generation per attempt, and excludes retries from additional quota usage.
- **Backend orchestration**: Coordinates project creation, task transitions, version records, quota checks, failures, and retries.
- **Entity persistence**: Provides user-scoped records for projects, build tasks, project versions, and usage quotas.
- **Mini-app previews**: Selects dashboard, coffee subscription, or team task manager variants using request keywords.
- **Template library**: Supports category filtering for Data, Marketing, Tools, and Commerce.
- **Changelog and blog**: Provides release filtering, static content, Markdown articles, prerendering, and sitemap generation.
- **Navigation and pricing**: Provides responsive navigation, account actions, Start Free CTAs, pricing tiers, and billing placeholders.
- **Supporting routes**: Includes sign-in, signup, authentication callback/error handling, logout callback, settings, protected admin routing, and under-construction pages.

# File Description Inventory

- **Workspace documentation**: `README.md`, `.atoms/`, `.wiki.md`, `docs/mission.md`, and `docs/plan.md`.
- **Backend authentication**: `app/backend/routers/auth.py` exposes resilient GET/POST logout handling and safe logout URL fallback.

- **Homepage**: `src/pages/Index.tsx` renders the generator and no longer includes the unrelated fixed footer login link.
- **Authentication state**: `src/hooks/useAuthStatus.ts` and `src/contexts/AuthContext.tsx` expose account state and resilient logout behavior.
- **Authentication pages**: Sign-in, signup, callback, error, and logout callback pages implement account flows.
- **Navigation**: `src/components/SiteHeader.tsx` renders authentication-aware account actions and responsive navigation.
- **Start Free flow**: `src/lib/startFree.ts`, `src/hooks/useStartFree.ts`, and `src/components/StartFreeIntentWatcher.tsx` preserve intent across authentication.
- **Project frontend**: `src/pages/Projects.tsx`, `src/pages/ProjectDetail.tsx`, `src/hooks/useProjects.ts`, and `src/lib/projects.ts` implement project queries, polling, retry, deletion, and detail views.

- **Blog and SEO**: `src/components/blog/`, `src/lib/blog.ts`, `prerender/`, `index.html`, and `public/robots.txt`.

# Usage

Install frontend dependencies and start development:

```bash
cd app/frontend
pnpm install
pnpm run dev
```

Run frontend checks and build:

```bash
pnpm run lint
pnpm run build
```

Install backend dependencies:

```bash
cd app/backend
python -m pip install -r requirements.txt
```

Apply database migrations when backend environment configuration is available:

```bash
alembic upgrade head
```

Run the backend using the configured FastAPI entry point or startup helper:

```bash
cd app
./start_app_v2.sh
```

To review authentication behavior, verify that the homepage has no duplicate footer login link, anonymous and authenticated navigation states are distinct, logout works through either request method, local state is cleared on logout errors, and users return to the homepage. Also verify project generation, quota usage, saved projects, project details, previews, and changelog content.
