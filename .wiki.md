# Project Summary

This project is an Atoms-style product demo for an AI application-generation platform. Users submit natural-language requests or select presets, receive a persisted six-stage generation workflow, and preview generated applications from stored artifacts.

The platform provides authenticated, user-scoped projects with persisted solutions, tasks, versions, test results, quotas, and object-storage artifacts. Generation now runs asynchronously: API requests persist and schedule work, while a background pipeline executes stages without holding database connections during AI or storage calls.

The primary generation gateway failure has been fixed. Short database transactions, improved connection-pool settings, snapshot reads, and resilient polling prevent backend workers from competing with browser requests for a single database connection. Gateway validation confirmed project creation and concurrent polling return successfully without 5xx errors or pool timeouts.

AI balance remains insufficient for a complete real-model six-stage run. Failed model attempts refund quota and clean up incomplete project records. Production startup should also remove `--reload`, and existing orphaned storage artifacts still require cleanup.

# Project Module Description

- **Landing and generator**: Accepts prompts and presets, creates persisted generation projects, polls progress, displays quota and gateway errors, and previews stored artifacts.
- **Asynchronous generation pipeline**: Separates stage claiming, external AI or storage work, and result persistence into short transactions.
- **Pipeline runner**: Executes six stages, supports project-level deduplication, atomic `pending` to `running` claims, independent sessions, process-restart recovery, and stale-stage reclamation after 600 seconds.
- **Authentication-aware navigation**: Provides account controls for authenticated users and login or Start Free actions for anonymous users.
- **Signup and Start Free flow**: Preserves anonymous intent through authentication and focuses the generator after login.
- **Project management**: Lists user projects, quota usage, progress, retries, deletion, loading, empty, anonymous, and error states.
- **Project detail**: Displays pipeline status, solution specifications, test reports, version history, artifact previews, and Open Preview actions.
- **Artifact storage**: Publishes generated applications to object storage and resolves preview locations from object keys.
- **Quota management**: Provides 20 Starter generations per natural month, deducts atomically, avoids duplicate retry charges, and refunds failed model attempts.
- **Concurrency and recovery**: Claims stages atomically, handles stale work, and prevents late workers from overwriting reclaimed stages.
- **Gateway resilience**: Uses request timeouts, 502/503/504 handling, exponential-backoff polling, short scheduling windows, and connection-pool configuration overrides.
- **Backend orchestration**: Coordinates ownership, task transitions, AI calls, artifact publication, versions, failures, retries, quotas, and cleanup.
- **Entity persistence**: Stores user-scoped projects, build tasks, quotas, solutions, artifacts, versions, and test results.
- **Template library**: Supports Data, Marketing, Tools, and Commerce filtering.
- **Changelog and blog**: Provides release filtering, version navigation, Markdown content, prerendering, and sitemap generation.
- **Navigation and pricing**: Provides responsive navigation, account actions, Start Free CTAs, pricing tiers, and billing placeholders.
- **Supporting routes**: Includes sign-in, signup, auth callbacks and errors, logout callback, settings, protected admin routing, and under-construction pages.
- **Verification and documentation**: Includes pipeline, quota-refund, gateway-timeout, AI, storage, architecture, decision, and progress verification records.

# File Description Inventory

- **Database configuration**: `app/backend/core/database.py` configures async sessions, serverless connection pools, timeouts, and environment overrides.
- **Application entry points**: `app/backend/main.py` and `lambda_handler.py` expose FastAPI and serverless handlers.
- **Generation API**: `app/backend/routers/generation.py` handles creation, progress snapshots, retries, scheduling, and quota errors.
- **Project API**: `app/backend/routers/projects.py` handles user-scoped listing, detail retrieval, deletion, and previews.
- **Pipeline orchestration**: `app/backend/services/generation.py` performs short-transaction stage claiming, external work, result commits, failure handling, stale recovery, and quota refunds.
- **Background execution**: `app/backend/services/pipeline_runner.py` advances scheduled generation stages independently from HTTP request sessions.
- **AI integration**: `app/backend/services/generation_ai.py` and `aihub.py` call configured models, manage timeouts and pooled clients, and recover malformed structured output.
- **Artifact handling**: `app/backend/services/generation_artifacts.py` creates generated products and uploads them to object storage.
- **Storage integration**: `app/backend/services/storage.py` resolves object keys into preview responses.
- **Schema and migrations**: `app/backend/models/`, `schemas/`, and `alembic/versions/` define persisted entities and database evolution.
- **Verification scripts**: `verify_stage3.py` validates AI and storage, `verify_quota_refund.py` validates failed-generation cleanup, `verify_pipeline.py` exercises the workflow, and `verify_gateway_timeout.py` validates creation and concurrent polling.
- **Frontend project state**: `src/hooks/useProjects.ts` and `src/lib/projects.ts` implement timeout handling, gateway error classification, backoff polling, retries, deletion, and project queries.
- **Frontend shell and pages**: `src/App.tsx`, `src/main.tsx`, and `src/pages/` define routes and product views.
- **Authentication and navigation**: Auth hooks, contexts, callbacks, `SiteHeader.tsx`, and Start Free helpers manage account state and intent.
- **Content and SEO**: `src/data/`, blog components, `src/lib/blog.ts`, `prerender/`, `index.html`, and `public/robots.txt` provide site content and indexing support.
- **Tooling and evidence**: Package manifests, lockfiles, Vite, TypeScript, ESLint, Tailwind, PostCSS, and runtime logs support development and diagnostics.

# Usage

Install frontend dependencies and start development:

```bash
cd app/frontend
pnpm install
pnpm run dev
```

Run frontend checks and production build:

```bash
pnpm run lint
pnpm run build
```

Install backend dependencies:

```bash
cd app/backend
python -m pip install -r requirements.txt
```

Apply database migrations when backend configuration is available:

```bash
alembic upgrade head
```

Run the application with the configured FastAPI entry point or startup helper:

```bash
cd app
./start_app_v2.sh
```

Production deployments should start without `--reload` so background workers are not interrupted by development reloads.

Run verification scripts:

```bash
cd app/backend
python verify_stage3.py
python verify_quota_refund.py
python verify_gateway_timeout.py
python verify_pipeline.py
```

`verify_gateway_timeout.py` validates project creation latency, database persistence, concurrent polling, and the absence of connection-pool failures. The complete pipeline verification requires sufficient external AI balance.

The latest validation passed backend compilation, frontend lint, frontend production build, gateway-level creation and polling tests, concurrent polling, quota refund behavior, and rendering checks. A complete real-model six-stage run remains blocked by insufficient AI balance.
