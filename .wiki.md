# Project Summary

This project is an Atoms-style product demo for an AI application-generation platform. Users submit natural-language requests or select presets, receive persisted multi-stage generation workflows, and preview generated applications from stored artifacts.

The platform provides authenticated, user-scoped projects with persisted solutions, tasks, versions, test results, quotas, and object-storage artifacts. Generation runs asynchronously through independently persisted stages and background workers.

Stage 4 testing is implemented end to end. It supports AI-assisted test-case generation, deterministic execution against generated artifacts, execution history, manual test-case CRUD, user isolation, and project cleanup. Test generation is connected from the frontend button through the API, orchestration service, AI output function, and database persistence. It requires a completed artifact and available AI quota; insufficient balance returns an explicit error without creating fabricated cases.

# Project Module Description

- **Landing and generator**: Accepts prompts and presets, creates projects, polls progress, displays quota and gateway errors, and previews generated applications.
- **Asynchronous generation pipeline**: Executes persisted generation stages through short database transactions and independent worker sessions.
- **Pipeline runner**: Claims stages, prevents project-level duplicates, recovers after restarts, and reclaims stale stages.
- **Authentication and authorization**: Supports OIDC, PKCE, platform-token exchange, JWT verification, protected routes, logout callbacks, and user-scoped resources.
- **Project management**: Lists projects, shows quota and progress, supports retries and deletion, and handles loading, empty, anonymous, and error states.
- **Project detail**: Displays pipeline status, solution specifications, version history, artifact previews, preview actions, and the testing panel.
- **Artifact storage and preview**: Publishes generated applications to object storage and resolves preview locations dynamically from stored artifact keys.
- **Quota management**: Provides Starter generation quotas, atomic deductions, duplicate-retry protection, and refunds for failed model attempts.
- **Backend orchestration**: Coordinates ownership, stage transitions, AI calls, artifact publication, versions, failures, retries, quota handling, testing, and cleanup.
- **Test-case management**: Generates 6–10 structured cases from persisted solutions and real generated artifact source, validates output limits, deduplicates cases, and preserves manually created cases during regeneration.
- **Test execution**: Runs deterministic assertions against current artifact source code, excludes disabled cases, persists aggregate statistics and per-case results, and supports historical run queries.
- **Test Suite UI**: Provides test generation, execution, result summaries, history switching, and manual create/edit/enable/disable/delete actions with loading, empty, failure, and success states.
- **Entity persistence**: Stores user-scoped projects, build tasks, quotas, solutions, artifacts, versions, test cases, test runs, and test results.
- **Reliability and diagnostics**: Handles timeouts, gateway errors, stale work, idempotent operations, connection-pool pressure, health checks, structured logs, and telemetry controls.
- **Template library**: Supports Data, Marketing, Tools, and Commerce filtering.
- **Changelog and blog**: Provides release filtering, version navigation, Markdown content, prerendering, and sitemap generation. The release history contains eight versions and 43 entries, with `v0.8.0` marked as latest.
- **Navigation and pricing**: Provides responsive navigation, account actions, Start Free CTAs, pricing tiers, and billing placeholders.
- **Supporting routes**: Includes sign-in, signup, authentication callbacks and errors, logout callback, settings, administration, and under-construction pages.
- **Roadmap planning**: Stage 4 testing is complete. Future work proceeds with bug submission and automated repair, conversational incremental editing with rollback, then custom domains and team collaboration.
- **Documentation**: Maintains product, architecture, planning, frontend, backend, changelog, progress, and verification documentation under `docs/` and `.atoms/`.

- **Testing data models**: `app/backend/models/test_cases.py` and `test_runs.py` define persisted test cases and execution records. Related metadata is stored under `data_models/`.
- **Testing services**: `app/backend/services/test_cases.py` handles case generation and CRUD; `test_runs.py` handles execution and history; `test_suite.py` coordinates suite operations and artifact readiness.
- **Testing routers**: `app/backend/routers/test_cases.py`, `test_runs.py`, and `test_suite.py` expose test-case, execution, history, and generation endpoints.
- **Testing migrations**: Alembic revisions update database structures required by testing models and related schema changes.
- **AI integration**: `app/backend/services/generation_ai.py` centralizes model calls and writes validated structured cases from the persisted plan and artifact source.
- **Generation API**: `app/backend/routers/generation.py` handles project creation, progress snapshots, retries, scheduling, quota errors, and testing-related integration points.
- **Project API and cleanup**: `app/backend/routers/projects.py` handles user-scoped project operations, preview resolution, and cleanup of test cases and runs during project deletion.
- **Verification**: `app/backend/verify_test_suite.py` validates generation constraints, deterministic execution, result aggregation, disabled-case handling, history ordering, user isolation, deletion behavior, and artifact-backed workflows.
- **Frontend project state**: `src/hooks/useProjects.ts` and `src/lib/projects.ts` implement project queries, timeout handling, gateway-error classification, backoff polling, retries, deletion, and testing API access.
- **Testing interface**: `src/components/TestSuitePanel.tsx` provides the connected test-generation workflow, execution, history, result summaries, and manual CRUD.
- **Project detail integration**: `src/pages/ProjectDetail.tsx` embeds the testing panel alongside project status, solution, version, and preview content.
- **Platform changelog**: `docs/changelog.md` mirrors `app/frontend/src/data/changelog.ts`, recording eight releases from `v0.8.0` through `v0.1.0`. It is distinct from generated-project version history stored in `project_versions`.
- **Application entry points**: `app/backend/main.py` and `lambda_handler.py` expose FastAPI and serverless handlers.
- **Database configuration**: `app/backend/core/database.py` configures asynchronous sessions, pools, timeouts, pre-ping behavior, and environment overrides.
- **Pipeline orchestration**: `app/backend/services/generation.py` performs stage claiming, external work, result commits, failure handling, stale recovery, and quota refunds.
- **Background execution**: `app/backend/services/pipeline_runner.py` advances scheduled stages with independent database sessions.
- **Artifact and storage handling**: `generation_artifacts.py` publishes generated products and records artifact keys; `storage.py` resolves keys into preview responses without persisting resolved preview addresses.
- **Schemas and migrations**: `models/`, `schemas/`, and `alembic/versions/` define persisted entities, API contracts, and database evolution.
- **Content and SEO**: `src/data/`, blog components, `src/lib/blog.ts`, `prerender/`, `index.html`, and `public/robots.txt` provide site content and indexing support.
- **Tooling and runtime evidence**: Package manifests, lockfiles, Vite, TypeScript, ESLint, Tailwind, PostCSS, and application logs support development and diagnostics.

# Usage

Install frontend dependencies and start development:

```bash
cd app/frontend
pnpm install
pnpm run dev
```

Run frontend checks and production build:

```bash
pnpm run lint
pnpm run build
```

Install backend dependencies:

```bash
cd app/backend
python -m pip install -r requirements.txt
```

Configure the backend according to `docs/backend.md`, including database, authentication, AI, object-storage, connection-pool, and diagnostic settings.

Apply database migrations:

```bash
cd app/backend
alembic upgrade head
```

Run the application with the configured FastAPI entry point or startup helper:

```bash
cd app
./start_app_v2.sh
```

Production deployments should run without reload mode so background workers are not interrupted by development reloads.

Run backend verification:

```bash
cd app/backend
python verify_stage3.py
python verify_quota_refund.py
python verify_gateway_timeout.py
python verify_pipeline.py
python verify_test_suite.py
```

Complete AI-assisted test-generation verification requires sufficient external AI balance and a project with a published artifact. Deterministic test execution, CRUD, and history verification can run without a model call against existing artifacts.
