# Project Summary

This project is an Atoms-style product demo for an AI application-generation platform. Users submit natural-language requests or select presets, then receive persisted, multi-stage generation workflows and previews of generated applications from stored artifacts.

The platform provides authenticated, user-scoped projects with persisted solutions, tasks, versions, test results, quotas, and object-storage artifacts. Generation runs asynchronously through independently persisted stages and background workers.

Current capabilities include real model-driven generation, artifact publication and previews, authentication, project management, quota handling, retries, recovery behavior, gateway resilience, and synchronized product, frontend, backend, architecture, release, and progress documentation. The roadmap documentation now consistently places test-case workflows before bug repair, followed by conversational incremental editing and version rollback, then custom domains and collaboration.

# Project Module Description

- **Landing and generator**: Accepts prompts and presets, creates projects, polls progress, displays quota and gateway errors, and previews generated applications.
- **Asynchronous generation pipeline**: Executes persisted generation stages through short database transactions and independent worker sessions.
- **Pipeline runner**: Claims stages, prevents project-level duplicates, recovers after restarts, and reclaims stale stages.
- **Authentication and authorization**: Supports OIDC, PKCE, platform-token exchange, JWT verification, protected routes, logout callbacks, and user-scoped resources.
- **Project management**: Lists projects, shows quota and progress, supports retries and deletion, and handles loading, empty, anonymous, and error states.
- **Project detail**: Displays pipeline status, solution specifications, test reports, version history, artifact previews, and preview actions.
- **Artifact storage and preview**: Publishes generated applications to object storage and resolves preview locations dynamically from stored artifact keys.
- **Quota management**: Provides Starter generation quotas, atomic deductions, duplicate-retry protection, and refunds for failed model attempts.
- **Backend orchestration**: Coordinates ownership, stage transitions, AI calls, artifact publication, versions, failures, retries, quota handling, and cleanup.
- **Entity persistence**: Stores user-scoped projects, build tasks, quotas, solutions, artifacts, versions, and test results.
- **Reliability and diagnostics**: Handles timeouts, gateway errors, stale work, idempotent operations, connection-pool pressure, health checks, structured logs, and telemetry controls.
- **Template library**: Supports Data, Marketing, Tools, and Commerce filtering.
- **Changelog and blog**: Provides release filtering, version navigation, Markdown content, prerendering, and sitemap generation. The release history contains eight versions and 43 entries, with `v0.8.0` marked as latest.
- **Navigation and pricing**: Provides responsive navigation, account actions, Start Free CTAs, pricing tiers, and billing placeholders.
- **Supporting routes**: Includes sign-in, signup, authentication callbacks and errors, logout callback, settings, administration, and under-construction pages.
- **Roadmap planning**: Tracks completed stages one through three and sequences future work as test-case generation and history, bug submission and automated repair, conversational incremental editing with rollback, then custom domains and team collaboration.
- **Documentation**: Maintains product, architecture, planning, frontend, backend, changelog, progress, and verification documentation under `docs/` and `.atoms/`.

- **Frontend development guide**: `docs/frontend.md` documents frontend architecture, routes, prerendering, generation flow, API contracts, polling, authentication, conventions, tooling, acceptance requirements, and future conversational editing and version comparison work.
- **Backend development guide**: `docs/backend.md` documents backend configuration, APIs, authentication, persistence, pipeline behavior, AI integration, storage, reliability, verification, and development rules.

- **Root documentation index**: `README.md` links to product, architecture, frontend, backend, changelog, and planning documentation.
- **Application entry points**: `app/backend/main.py` and `lambda_handler.py` expose FastAPI and serverless handlers.
- **Database configuration**: `app/backend/core/database.py` configures asynchronous sessions, pools, timeouts, pre-ping behavior, and environment overrides.

- **Project API**: `app/backend/routers/projects.py` handles user-scoped listing, detail retrieval, deletion, and preview resolution.
- **Pipeline orchestration**: `app/backend/services/generation.py` performs stage claiming, external work, result commits, failure handling, stale recovery, and quota refunds.
- **Background execution**: `app/backend/services/pipeline_runner.py` advances scheduled stages with independent database sessions.
- **AI integration**: `generation_ai.py` and `aihub.py` select models, enforce timeouts, normalize upstream failures, parse structured JSON, repair limited formatting issues, and validate fields.
- **Artifact and storage handling**: `generation_artifacts.py` publishes generated products and records artifact keys; `storage.py` resolves keys into preview responses without persisting resolved preview addresses.
- **Schemas and migrations**: `models/`, `schemas/`, and `alembic/versions/` define persisted entities, API contracts, and database evolution.
- **Verification scripts**: The verification scripts cover AI and storage, quota refunds, complete pipeline behavior, gateway timeout handling, persistence, and concurrent polling.
- **Frontend project state**: `src/hooks/useProjects.ts` and `src/lib/projects.ts` implement project queries, timeout handling, gateway-error classification, backoff polling, retries, and deletion.

# Usage

Install frontend dependencies and start development:

```bash
cd app/frontend
pnpm install
pnpm run dev
```

Run frontend checks and production build:

```bash
pnpm run lint
pnpm run build
```

Install backend dependencies:

```bash
cd app/backend
python -m pip install -r requirements.txt
```

Configure the backend according to `docs/backend.md`, including database, authentication, AI, object-storage, connection-pool, and diagnostic settings.

Apply database migrations:

```bash
cd app/backend
alembic upgrade head
```

Run the application with the configured FastAPI entry point or startup helper:

```bash
cd app
./start_app_v2.sh
```

Production deployments should run without reload mode so background workers are not interrupted by development reloads.

Run backend verification:

```bash
cd app/backend
python verify_stage3.py
python verify_quota_refund.py
python verify_gateway_timeout.py
python verify_pipeline.py
```

Complete pipeline verification requires sufficient external AI balance.
