# Project Summary

This project is an Atoms-style product demo for an AI application-generation platform. Users submit natural-language requests or select presets, receive a persisted six-stage generation workflow, and preview generated applications from stored artifacts.

The platform provides authenticated, user-scoped projects with persisted solutions, tasks, versions, test results, quotas, and object-storage artifacts. Generation runs asynchronously: API requests persist and schedule work, while background workers execute stages independently of long-lived database transactions.

The current implementation includes the stage-three generation flow, asynchronous backend execution, object-key-based preview resolution, iframe previews, quota refunds, retry handling, gateway resilience, and synchronized product and engineering documentation.

# Project Module Description

- **Landing and generator**: Accepts prompts and presets, creates generation projects, polls progress, displays quota and gateway errors, and previews generated applications.
- **Asynchronous generation pipeline**: Executes six persisted stages through short database transactions and independent worker sessions.
- **Pipeline runner**: Supports stage claiming, project-level deduplication, restart recovery, and stale-stage reclamation after 600 seconds.
- **Authentication and authorization**: Supports OIDC, PKCE, platform-token exchange, JWT verification, protected routes, logout callbacks, and user-scoped resources.
- **Project management**: Lists projects, quota usage, progress, retries, deletion, loading, empty, anonymous, and error states.
- **Project detail**: Displays pipeline status, solution specifications, test reports, version history, artifact previews, and preview actions.
- **Artifact storage**: Publishes generated applications to object storage and resolves preview locations dynamically from artifact keys.
- **Preview delivery**: Uses iframe previews backed by resolved artifact locations; preview URLs are not persisted as project data.
- **Quota management**: Provides 20 Starter generations per natural month, performs atomic deductions, avoids duplicate retry charges, and refunds failed model attempts.
- **Backend orchestration**: Coordinates ownership, task transitions, AI calls, artifact publication, versions, failures, retries, quotas, and cleanup.
- **Entity persistence**: Stores user-scoped projects, build tasks, quotas, solutions, artifacts, versions, and test results.
- **Reliability**: Handles timeouts, gateway errors, stale work, idempotent operations, connection-pool pressure, and recovery paths.
- **Health and diagnostics**: Provides health checks, structured logging, telemetry controls, and runtime diagnostics.
- **Template library**: Supports Data, Marketing, Tools, and Commerce filtering.
- **Changelog and blog**: Provides release filtering, version navigation, Markdown content, prerendering, and sitemap generation.
- **Navigation and pricing**: Provides responsive navigation, account actions, Start Free CTAs, pricing tiers, and billing placeholders.
- **Supporting routes**: Includes sign-in, signup, auth callbacks and errors, logout callback, settings, protected administration, and under-construction pages.
- **Verification and documentation**: Includes pipeline, quota-refund, gateway-timeout, AI, storage, architecture, planning, progress, and backend development documentation.

- **Product and architecture documentation**: `docs/mission.md`, `docs/plan.md`, `.atoms/ARCHITECTURE.md`, `.atoms/ATOMS.md`, and `.atoms/PROGRESS.md` describe scope, state models, module boundaries, implementation progress, reliability decisions, and remaining work.
- **Backend development guide**: `docs/backend.md` documents the backend stack, directory responsibilities, lifecycle, environment variables, authentication, database boundaries, data models, pipeline behavior, API contracts, AI integration, storage, reliability, verification, and development rules.
- **Frontend guide**: `app/frontend/README.md` documents actual routes, authentication callbacks, frontend structure, and the asynchronous generation-to-iframe-preview flow.
- **Database configuration**: `app/backend/core/database.py` configures async sessions, connection pools, timeouts, pre-ping behavior, and environment overrides.
- **Application entry points**: `app/backend/main.py` and `lambda_handler.py` expose FastAPI and serverless handlers.
- **Generation API**: `app/backend/routers/generation.py` handles creation, progress snapshots, retries, scheduling, and quota errors.
- **Project API**: `app/backend/routers/projects.py` handles user-scoped listing, detail retrieval, deletion, and preview resolution.
- **Pipeline orchestration**: `app/backend/services/generation.py` performs stage claiming, external work, result commits, failure handling, stale recovery, and quota refunds.
- **Background execution**: `app/backend/services/pipeline_runner.py` advances scheduled stages using independent database sessions.
- **AI integration**: `app/backend/services/generation_ai.py` and `aihub.py` select models, enforce timeouts, normalize upstream failures, parse structured JSON, perform limited repair, and validate fields.
- **Artifact handling**: `app/backend/services/generation_artifacts.py` creates generated products, uploads them to object storage, and records artifact keys without persisting resolved preview addresses.
- **Storage integration**: `app/backend/services/storage.py` resolves object keys into preview responses and checks object accessibility.
- **Schema and migrations**: `app/backend/models/`, `schemas/`, and `alembic/versions/` define persisted entities, API contracts, and database evolution.
- **Health, logging, and telemetry**: Core diagnostics modules expose health behavior and configurable runtime observability.
- **Verification scripts**: `verify_stage3.py` validates AI and storage, `verify_quota_refund.py` validates failed-generation cleanup, `verify_pipeline.py` exercises the workflow, and `verify_gateway_timeout.py` validates creation and concurrent polling.
- **Frontend project state**: `src/hooks/useProjects.ts` and `src/lib/projects.ts` implement timeout handling, gateway error classification, backoff polling, retries, deletion, and project queries.
- **Frontend shell and pages**: `src/App.tsx`, `src/main.tsx`, and `src/pages/` define routes and product views, including logout callback and iframe preview states.
- **Authentication and navigation**: Auth hooks, contexts, callbacks, `SiteHeader.tsx`, and Start Free helpers manage account state and intent.
- **Content and SEO**: `src/data/`, blog components, `src/lib/blog.ts`, `prerender/`, `index.html`, and `public/robots.txt` provide site content and indexing support.

# Usage

Install frontend dependencies and start development:

```bash
cd app/frontend
pnpm install
pnpm run dev
```

Run frontend checks and production build:

```bash
pnpm run lint
pnpm run build
```

Install backend dependencies:

```bash
cd app/backend
python -m pip install -r requirements.txt
```

Configure the backend environment according to `docs/backend.md`, including database, authentication, AI, object-storage, connection-pool, and diagnostic settings.

Apply database migrations:

```bash
cd app/backend
alembic upgrade head
```

Run the application with the configured FastAPI entry point or startup helper:

```bash
cd app
./start_app_v2.sh
```

Production deployments must start without reload mode so background workers are not interrupted by development reloads.

Run backend verification:

```bash
cd app/backend
python verify_stage3.py
python verify_quota_refund.py
python verify_gateway_timeout.py
python verify_pipeline.py
```

The gateway verification covers project creation latency, persistence, concurrent polling, and connection-pool failures. Complete pipeline verification requires sufficient external AI balance.
