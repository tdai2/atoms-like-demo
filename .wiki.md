# Project Summary

This project is an Atoms-style product demo for an AI application-generation platform. Users submit natural-language app requests or choose presets, follow a six-stage generation workflow, and preview generated applications from persisted artifacts.

The platform supports authenticated, user-scoped projects with persisted solutions, tasks, versions, test results, quotas, and object-storage artifacts. A read-only persistence audit confirmed that the database schema and user isolation support the complete project lifecycle, but the current database contains no persisted projects. One real account has consumed one quota unit, consistent with a project that was later deleted.

The audit also identified orphaned object-storage artifacts left after project deletion, including `projects/2/v1/index.html`, a blank-key object, and a verification artifact. No code was modified and no build was run during the audit.

# Project Module Description

- **Landing and generator**: Accepts prompts and presets, starts persisted generation projects, polls stage progress, displays quota errors, and renders stored-artifact previews.
- **Authentication-aware navigation**: Shows account controls for authenticated users and login or Start Free actions for anonymous users.
- **Logout handling**: Clears local state, supports callback routing and fallback behavior, and preserves dark styling.
- **Signup and Start Free flow**: Preserves anonymous intent through signup and authentication, then focuses the generator after login.
- **Real generation pipeline**: Runs requirements parsing, solution planning, code generation, build validation, test validation, and artifact publishing through configured AI and storage services.
- **Structured-output recovery**: Repairs malformed model JSON locally before attempting stricter fallback handling.
- **Project management**: Lists user projects, displays quota usage, and supports deletion, polling, retry, loading, empty, anonymous, and error states.
- **Project detail**: Shows pipeline status, solution specifications, test reports, version history, stored-artifact previews, and Open Preview actions.
- **Artifact storage**: Uploads generated products to object storage and resolves preview addresses from object keys at request time.
- **Quota management**: Provides 20 Starter generations per natural month, deducts atomically per attempt, avoids duplicate retry charges, and refunds failed model attempts.
- **Concurrent execution control**: Atomically claims stages and recovers stale in-progress work.
- **Backend orchestration**: Coordinates ownership, task transitions, AI calls, artifact publication, versions, failures, retries, quota handling, and cleanup.
- **Entity persistence**: Stores user-scoped projects, build tasks, quotas, solutions, artifacts, versions, and test results. The schema has non-null `user_id` fields and user indexes across the primary business tables.
- **Persistence audit**: Verifies database connectivity, table structure, account isolation, project relationships, quota records, and object-storage consistency. The current database has zero projects, tasks, and versions; two quota records remain.
- **Storage cleanup status**: Project deletion removes database records but does not currently remove corresponding object-storage artifacts, allowing orphaned artifacts to remain.
- **Template library**: Supports filtering for Data, Marketing, Tools, and Commerce.
- **Changelog and blog**: Provides release filtering, version navigation, static content, Markdown articles, prerendering, and sitemap generation. New releases are added at the top of `src/data/changelog.ts`.
- **Navigation and pricing**: Provides responsive navigation, account actions, Start Free CTAs, pricing tiers, and billing placeholders.
- **Supporting routes**: Includes sign-in, signup, authentication callback/error handling, logout callback, settings, protected admin routing, and under-construction pages.
- **Documentation maintenance**: Tracks Stage Three architecture, decisions, progress, verification results, persistence findings, and external blockers.

# Usage

Install frontend dependencies and start development:

```bash
cd app/frontend
pnpm install
pnpm run dev
```

Run frontend checks and build:

```bash
pnpm run lint
pnpm run build
```

Install backend dependencies:

```bash
cd app/backend
python -m pip install -r requirements.txt
```

Apply database migrations when backend environment configuration is available:

```bash
alembic upgrade head
```

Run the backend using the configured FastAPI entry point or startup helper:

```bash
cd app
./start_app_v2.sh
```

Run Stage Three verification from the backend directory:

```bash
cd app/backend
python verify_stage3.py
python verify_quota_refund.py
python verify_pipeline.py
```

`verify_stage3.py` validates model calls, artifact upload and retrieval, public preview resolution, and successful parsing, planning, and code generation. `verify_quota_refund.py` validates unavailable-model refunds and partial-record cleanup. The full pipeline requires sufficient external AI balance.

The latest activity was a read-only persistence audit. It confirmed one real account, zero persisted projects, tasks, and versions, two quota records, intact user-scoped schema relationships, and orphaned storage objects. No source changes or build verification were performed as part of that audit.
